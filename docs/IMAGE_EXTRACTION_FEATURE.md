# Image Extraction Feature

## Overview

The image extraction feature automatically detects and saves images generated by multimodal AI models (like `google/gemini-2.5-flash-image`) through OpenRouter and OpenAI APIs. Images are extracted from API responses and saved to disk with configurable naming and validation against file constraints.

## Features

- **Automatic Detection**: Images in multimodal responses are automatically detected
- **Opt-in Configuration**: Enable per-agent via `extract_images` config
- **Security Enforced**: All images validated against `file_constraints.write_patterns`
- **Flexible Naming**: Sequential or turn-based filename strategies
- **Base64 Support**: Binary image data handled via base64 encoding
- **Backwards Compatible**: Zero impact on existing text-only flows

## Configuration

### Agent Config

Add `extract_images` to any agent configuration:

```javascript
{
    name: 'RENDER_VIEWS',
    model: 'google/gemini-2.5-flash-image',

    extract_images: {
        enabled: true,              // Enable image extraction
        prefix: 'mockup',           // Filename prefix
        naming: 'sequential',       // 'sequential' | 'turn-based'
        format: 'png',              // Default format: 'png' | 'jpg' | 'webp'
    },

    file_constraints: {
        write_patterns: ['**/*.png', '**/*.jpg', '**/*.svg', '**/*.html'],
    },
}
```

### Naming Strategies

#### Sequential
Images numbered continuously across all turns:
- `mockup-001.png` (turn 1, image 0)
- `mockup-002.png` (turn 1, image 1)
- `mockup-003.png` (turn 2, image 0)

#### Turn-based
Images grouped by turn:
- `mockup-t1-0.png` (turn 1, image 0)
- `mockup-t1-1.png` (turn 1, image 1)
- `mockup-t2-0.png` (turn 2, image 0)

## How It Works

### 1. API Response Processing

When a multimodal model generates images, the API returns content in this format:

```javascript
{
    content: [
        { type: 'text', text: 'Here is your mockup:' },
        {
            type: 'image_url',
            image_url: {
                url: 'data:image/png;base64,iVBORw0KGgo...',
                detail: 'high'
            }
        }
    ]
}
```

### 2. Content Extraction

The adapter's `_extractMultimodalContent()` method separates text and images:

```javascript
{
    textContent: 'Here is your mockup:',
    images: [
        {
            url: 'data:image/png;base64,iVBORw0KGgo...',
            detail: 'high'
        }
    ]
}
```

### 3. Image Saving

If `extract_images.enabled` is true, the executor:
1. Generates filename based on naming strategy
2. Validates against `file_constraints.write_patterns`
3. Decodes base64 or downloads from URL
4. Saves via `write_file` tool with `encoding: 'base64'`

### 4. Logging

```
[Image Extraction] Processing 2 image(s)...
🖼️  Saved image: mockup-001.png (45 KB)
🖼️  Saved image: mockup-002.png (67 KB)
```

### Security

- **File Constraints**: All images validated against `file_constraints.write_patterns`
- **Path Validation**: Images saved through existing `write_file` tool with full security checks
- **Sandbox Isolation**: Image processing runs inside Docker VM
- **No Arbitrary Writes**: Cannot bypass file constraint patterns

### Error Handling

- Invalid data URIs: Logged and skipped
- Download failures: Logged and skipped
- File constraint violations: Logged and skipped
- Individual image failures don't stop processing of other images

## Limitations

1. **Image Generation Only**: Feature extracts images from responses, doesn't trigger generation
2. **No Image Editing**: Cannot modify or process extracted images
3. **Format Detection**: Default format used if not detectable from data URI
4. **Size Limits**: Inherits Docker/filesystem size limits

## Troubleshooting

### Images Not Being Saved

1. **Check configuration**: Ensure `extract_images.enabled: true`
2. **Check file constraints**: Verify image extensions in `write_patterns`
3. **Check logs**: Look for `[Image Extraction]` messages
4. **Check model**: Ensure model actually generates images

### File Constraint Errors

```
⚠️  Skipping mockup-001.png - not allowed by file_constraints
```

**Solution**: Add image extensions to `file_constraints.write_patterns`:

```javascript
file_constraints: {
    write_patterns: ['**/*.png', '**/*.jpg', '**/*.webp']
}
```

### Invalid Data URI

```
✗ Failed to save image 0: Invalid data URI format
```

**Solution**: This indicates the model returned an unexpected format. Check trace files for the actual response format.

## Examples

### Basic Usage

```javascript
{
    name: 'IMAGE_GEN',
    model: 'google/gemini-2.5-flash-image',
    extract_images: {
        enabled: true,
        prefix: 'generated',
        naming: 'sequential',
        format: 'png',
    },
    file_constraints: {
        write_patterns: ['**/*.png'],
    },
}
```

### Multiple Formats

```javascript
{
    name: 'ASSET_GEN',
    model: 'google/gemini-2.5-flash-image',
    extract_images: {
        enabled: true,
        prefix: 'asset',
        naming: 'turn-based',
        format: 'jpg',
    },
    file_constraints: {
        write_patterns: ['**/*.jpg', '**/*.png', '**/*.webp'],
    },
}
```

### Disabled (Default)

```javascript
{
    name: 'TEXT_ONLY',
    model: 'mistralai/mistral-large',
    // No extract_images config = disabled
    file_constraints: {
        write_patterns: ['**/*.md', '**/*.txt'],
    },
}
```
